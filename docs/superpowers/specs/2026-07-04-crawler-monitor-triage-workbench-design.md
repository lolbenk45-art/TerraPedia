# 对撞爬虫监控页 · 分诊工作台重做（UX 定稿）

- 日期：2026-07-04
- 分支：`ux/crawler-collider-page`
- 目标文件：`data-query-app/pages/operations/crawler-monitor.vue`
- 交互原型：`.superpowers/brainstorm/237056-1783152187/content/final-design.html`（端口预览，gitignored）
- 前置：本次仅做**前端可用性重做**（信息架构 / 交互流程 / 文案 / 密度 / 配色对齐）。不改后端派发链路与 `domain.state` 契约（沿用 P2 已落地的权威 state）。

---

## 1. 背景与问题

页面 `crawler-monitor.vue`（约 7,524 行，单文件）是**基础域自动化爬取的监控 + 排查台**。管理员的核心诉求：一眼看出每个基础域的 wiki 数据**有没有更新、有没有去爬、是否保持最新**；出问题时能借助**日志 / 队列 / 历史 / 证据**快速定位。目前有 **10 个基础域**（会增长），尚无入库，重点是**爬取动作本身的健康度与可追溯性**。

当前页面的可用性问题（本次要解决）：

1. **"真实任务进度"太乱**：正在运行 + 历史 + 异常一大堆任务卡混排，分不清哪些要管、哪些只是记录。
2. **同一批任务被画了两三遍**：`队列和派发状态` 面板（executionOverviewRows）与 `真实任务进度` 面板（progressRows）内容高度重复，加上域总览的进度列，是页面臃肿的根因。
3. **术语晦涩**：队列标识 / 队列状态 / 阻塞者 / 证据 / 心跳 等词管理员看不懂。
4. **按钮语义不清 / 危险**：清空运行/队列、强制回收、终止任务，不确定点了会发生什么、会不会误删。
5. **五个顶层 Tab（域总览/队列/进度/报告/诊断）**：为排查一个域要在多个 Tab 间来回跳才能拼齐线索。

## 2. 设计目标

- **异常优先**：需要处理的域自动浮到最上面，健康的让路；域增多也不被淹没。
- **单域闭环**：排查一个域所需的一切（状态、诊断、任务历史、队列、产物、日志）集中在该域的详情里，不跳 Tab。
- **消除重复**：把三处重复的"任务"表示收敛为"域 → 任务历史"一处。
- **对齐主题**：严格使用项目令牌（`assets/css/variables.css`）——暖纸 `#f6f4ef` + 青绿 `#0d9488` + 淡彩状态（`--color-*-muted`），不再用高饱和大色块 / emoji 图标。

## 3. 信息架构（核心）

真实数据只有 **5 类对象**，除"基础域"外其余都从属于某个域：

| 对象 | 归属 |
|---|---|
| 基础域 ×10 | 主锚点（主页三段式） |
| 任务/执行（当前+排队+历史） | 收进**域详情 → 任务历史**（合并原 `队列`+`进度` 两个 Tab） |
| 报告 / 产物 / 日志 | 域详情 → 产物 / 日志；跨域进"系统 → 报告库" |
| 诊断（心跳/锁/质量/运行历史/图片归一化） | "系统"抽屉 |
| 自动派发设置 | "系统"抽屉 |

顶层从 **5 个 Tab → 单一分诊工作台 + 两个抽屉**。

### 3.1 主页：分诊工作台（三段式，纵向）

1. **状态条**：一句话健康度（"2 个域需要处理 · 1 正在爬"）+ 右上操作区
   - `活动`（打开活动抽屉）、`系统`（打开系统抽屉）、`清空…`（危险，二次确认）、`刷新`。
2. **KPI 行**（5 张）：基础域 / 正在爬取 / 需要处理(标红) / 今日已更新 / 自动派发。
3. **需要处理**区：只放需处理的域，做成**问题域大卡**（诊断原因一句话 + 关键数值 + 一键操作：强制释放并重试 / 终止 / 详情）。无异常时该区显示"全部正常"空态。
4. **全部基础域**区：默认**卡片板**（10 块，按状态淡彩底 + 圆点；卡住红点脉冲；运行中进度条流动微光；hover 右下角浮出快捷操作）。右上 `卡片板 / 表格` 切换 —— 表格为全宽多列密表（基础域/状态/新鲜度/当前任务/最近活动/下一步/操作），吸收高密度浏览需求。

排序：需处理 > 运行中 > 未跑 > 最新（沿用现有 diagnosisGroup / state 严重度阶梯）。

### 3.2 域详情：右侧抽屉（点卡/块/行滑入，宽 ~680px）

- **头部**：状态药丸（带脉冲）+ 域名 + 一行 `域名·任务编号·PID`（等宽代码块）+ **诊断横幅**（"为什么卡住 + 建议动作"，淡彩底 + 细色边）。
- **子标签**：概览 / 任务历史⑥ / 队列① / 产物④ / 日志。
  - **概览**：字段网格（3 列），含带时间的字段——当前状态、进度%、数据新鲜度、**本次开始**、**最近心跳(相对时间)**、**上次成功爬取**、被谁占用(PID)、任务编号·通道、速度/预计剩余、**上次运行结果**、累计次数、**下次自动扫描**；异常字段标红。下方操作按钮 + "为什么卡住"诊断块（含建议动作）。
  - **任务历史**：竖向时间线（白卡 + 彩色圆点节点 + 3px 细色边），每条含 时间/页数/结果原因。合并原 `队列`+`进度`。
  - **队列**：该域当前队列项（通道/位置/PID/状态）。
  - **产物**：富文件行（图标 + 文件名 + 路径 + 大小·时间），点击预览。
  - **日志**：终端风查看器 —— run.log/error.log 切换、ERROR/WARN/INFO 级别筛选、搜索高亮、行号、级别着色、实时跟随、复制路径/看完整。

### 3.3 系统 / 活动：右侧抽屉（次级内容，不占主页版面）

- **活动**：跨域任务流（按时间，不按域拆），判断"整体在不在跑"。
- **系统**：诊断（心跳/锁/质量/图片归一化）+ 报告库 + 自动派发设置（启用开关 / 扫描间隔 / 最近派发）。

## 4. 文案改口径（术语 → 口语）

| 现字段 | 新说法 |
|---|---|
| queueId / 队列标识 | 任务编号 |
| 阻塞者 / 占用 | 被谁占用 |
| 心跳 | 最近活动 / 最近心跳 |
| 证据 | 产物文件 |
| 强制回收 | 强制释放占用（并重试） |
| 状态：blocked/stalled/running… | 卡住 / 失败 / 超时 / 运行中 / 排队 / 最新 / 未跑 / 已完成 / 已取消 |

危险操作（清空运行/队列、终止并清理、强制释放）保留二次确认弹层，确认框内列出将影响的路径/域。

## 5. 视觉与动效（对齐 `variables.css`）

- 颜色：一律引用 `--color-*` 令牌；状态用 `--color-*-muted` 淡彩底 + 深字 + 小圆点。**禁止**整行高饱和填色。
- 图标：线性 SVG（现有 lucide-vue-next），不用 emoji。
- 圆角/阴影/间距：用 `--radius-*` / `--shadow-*`，4/8 间距节奏。
- 动效（150–300ms，`transform`/`opacity`，尊重 `prefers-reduced-motion`）：KPI 跳数、进度条流动微光、卡住脉冲、抽屉滑入 + 遮罩渐显、子标签淡入、刷新骨架、操作 toast、卡片 hover 上浮。

## 6. 实现策略（关键约束）

因涉及模板/脚本结构改动，会触碰旧的**源码字符串契约测试**。按用户偏好（[[feedback-testing]]）：**优先行为测试，避免脆的 `.vue` 源码匹配**。

1. **抽纯逻辑到 `.mjs`**：分诊分组（needsAttention / running / idle / healthy 的归类与排序）、域详情视图模型（把 domainRow + queue + progress + state 聚合成一个 `domainDetailViewModel`）、任务历史合并（executionOverview + progress 去重为一条任务流）、日志级别解析/筛选。放到 `data-query-app/utils/` 或 `pages/operations/` 同级，用 `node --test` 覆盖返回值。
2. **`crawler-monitor.vue` 收敛**：删除 `queue` / `progress` / `reports` 三个顶层面板与其重复渲染；新增分诊工作台主体 + 域详情抽屉 + 系统/活动抽屉。复用 P2 `domain.state`（status/nextAction/blocker/evidence）渲染，删除前端 fallback 合成（P3 收口点）。
3. **文件拆分**（服务本次目标，避免 7500 行单文件继续膨胀）：抽出 `CrawlerTriageBoard`、`DomainDetailDrawer`（含子标签子组件）、`LogViewer`、`SystemDrawer`、`ActivityDrawer` 等 SFC 子组件；主页面只做数据编排。
4. **契约测试**：重写为"页面挂载了模块 + 端点"的薄 smoke + 组件行为测试；删除大量 `assert.match(page, /regex/)` 源码断言。
5. **保留**：所有后端端点、控制动作（forceReclaim/cancel/dispatch）、`domain.state` 契约、报告预览抽屉逻辑。

## 7. 验收标准

- 主页默认呈现分诊三段式；有异常时问题域在最上，无异常显示正常空态。
- 点任一域 → 抽屉含 概览/任务历史/队列/产物/日志，五者数据来自现有 DTO，无重复面板。
- 页面不再有 `队列和派发状态` / `真实任务进度` / `报告` 三个顶层 Tab；其内容各有新归属。
- 术语按 §4 改口径；危险操作有二次确认。
- 配色全部来自 `variables.css` 令牌；无高饱和整行填色、无 emoji 图标。
- `node --test` 下 crawler 相关测试全绿；SFC parse/compile 通过；dev server（端口 3001）无 HMR 报错。

## 8. 非目标（YAGNI / 后续）

- 不改后端爬取逻辑与派发链路；若排查中发现真实功能缺陷，单独开 issue。
- 不做入库/数据质量深化（当前无入库）。
- 不做移动端专门适配（管理员桌面使用为主，但保持不横向滚动）。
- 暗色主题沿用现有令牌，不在本次专门设计。
