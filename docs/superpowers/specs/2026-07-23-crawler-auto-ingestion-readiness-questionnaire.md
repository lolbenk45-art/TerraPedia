## 1. 目标与完成标准

### 目标

让当前注册的全部爬虫/数据操作进入统一的分级自动化治理：每个域独立处于 L0、L1 或 L2，满足证据和安全门禁的域可以自动正式入库，异常域自动熔断、降级并通知 System Owner。

### 设计阶段完成标准

- 所有自动化、删除、审批、阈值、回滚、调度和页面边界均有唯一答案。
- 每个待实施阶段都有明确前置条件、文件范围、测试和人工验收边界。
- 计划不会把“操作已注册”误写成“已具备无人值守入库能力”。
- 真实 crawler/apply 仍需计划中的显式人工授权检查点。

### 本轮不做

- 不执行真实 crawler、import、backfill 或 apply。
- 不修改数据库、Redis V2 状态、运行时切换标记或现有数据产物。
- 不删除 V1、不部署生产、不新增外部数据源。

## 2. 当前审计事实

1. 当前 V2 已有 19 个稳定操作、精确 attempt 身份、租约、心跳、计划/结果证据和管理端操作目录。
2. acceptance manifest、freshness、manual refresh plan、operation plan 等只读契约测试通过 69/69。
3. Plan A 幂等套件通过 156/157；Town NPC rich-profile 测试受主 worktree MinIO 端口配置影响，当前不是环境无关门禁。
4. 数据维护链审计在干净 worktree 因默认 relation report 缺失而退出；当前证据链不能 clean-clone 重现。
5. backend refresh 计划同时存在默认 apply 动作和 manual-only apply 动作，不能用一个全局开关安全地全部自动化。
6. 因此当前判定是：监控/操作基础较成熟，但自动入库仍有 foundation gaps，尚未 feature-ready。

## 3. 已确认并锁定的决策

| 编号 | 已确认内容 |
| --- | --- |
| D1 | 采用分级自动化：L0 禁止自动写库，L1 审批后 apply，L2 自动 apply。 |
| D2 | 任何门禁、差异、apply 或 post-apply 验收异常都会熔断并自动降级。 |
| D3 | 最终范围覆盖当前全部注册操作及其维护域，但每个域独立晋级，不同时开放 L2。 |
| D4 | L2 可做父实体/作用域内关系差集删除和小比例实体软失活；硬删除、整域重建、越阈值删除必须转 L1。 |
| D5 | 每域使用版本化策略，绝对数量和比例双上限；历史波动只能额外拦截，不能自动放宽。 |
| D6 | 首次晋级 L2、熔断后恢复和阈值放宽必须由高权限方确认。 |
| D7 | 事务内失败自动回滚；提交后仅在 attempt 仍是最新写入、无后续/人工修改且快照完整时自动恢复。 |
| D8 | 变化检测触发增量任务，叠加低频错峰全量对账；同域串行、全局限并发。 |
| D9 | 只有固定 System Owner 能批准高风险操作；其他管理员只能查看、处理普通失败和提交建议。 |
| D10 | 页面实时告警并邮件通知 System Owner，同类事件聚合去重。 |
| D11 | 核心域每 6 小时检测，扩展域每日检测，每周错峰全量对账，来源变化可提前触发。 |
| D12 | 默认页面采用风险控制台；流水线控制塔和全域矩阵作为次级标签页。 |
| D13 | 复用 Redis V2 和现有 19 操作目录；页面不自行推断风险、命令或执行权限。 |

若需要推翻锁定项，请明确写 `推翻 D编号：新要求`，否则执行计划会将其视为不可变约束。
