## 1. 本次目标

### Goal

把当前 12 个注册动作的真实行为逐项说清楚，重新确定管理端应该如何表达：

- 检查更新
- 强制重新抓取
- 本地同步或转换
- dry-run 数据检查
- 数据库正式写入
- 运行中暂停
- 失败后继续或重新执行

### Success Criteria

- 每个域的默认操作有唯一、真实的业务含义。
- 管理员在点击前能知道是否访问 Wiki、是否覆盖本地文件、是否连接或写入数据库。
- “无变化”“重新抓取完成”“dry-run 完成”“数据库写入完成”不再统一显示成普通“完成”。
- 暂停、继续、断点续传、重新执行和重新排队不再混用。
- 当前状态和上次运行结果分开表达。
- 所有未确定项都由本文回填，不由实现人员自行猜测。

### Out Of Scope

- 本文不决定具体前端布局和视觉稿。
- 本文不定义接口字段和代码实现方式。
- 本文不扩大数据级断点续传范围。
- 本文不授权任何真实爬取、Redis 修改或数据库写入。
- 本文不使用假数据替代任务计划、进度或运行结果。

## 2. 术语先统一

| 术语 | 本文中的含义 |
| --- | --- |
| V2 | 队列、attempt、心跳、日志、暂停、重试等运行治理系统；不是具体爬虫策略 |
| 检查更新 | 查询来源 revision 或本地状态，只有发现变化或缺失时才抓取 |
| 强制重新抓取 | 不因 revision 未变化而跳过，重新访问来源并覆盖约定输出 |
| 同步 | 含义尚待回填，可能是更新本地文件，也可能是写入业务数据库 |
| 运行中暂停 | 冻结当前进程，之后恢复同一个进程；不创建新 attempt |
| 数据级断点续传 | 原进程失败后，新 attempt 从有效 checkpoint 接着处理剩余数据 |
| retry | 创建新的 attempt 再执行；是否接断点由动作能力决定 |
| dry-run | 读取真实来源或数据库并产生真实差异报告，但不正式写入业务数据库 |
| 当前状态 | 域此刻处于空闲、排队、运行、暂停等哪种状态 |
| 上次结果 | 最近一次真实任务是无变化、抓取完成、失败、取消或写库完成 |

## 3. 已核实的当前实现

### 3.1 当前运行链路

```text
管理端读取 V2 overview
  -> 后端返回 12 个注册域、live attempt 和 attempt history
  -> 前端把当前域状态与最近一次终态 attempt 投影到域卡片
  -> 点击开始时固定提交 resumeMode=fresh
  -> 后端从动作注册表解析真实命令
  -> V2 入队、领取、启动进程
  -> 进程上报心跳、进度、日志和产物
  -> 完成或失败后进入 attempt history
```

### 3.2 当前状态允许的操作

| 当前状态 | 后端当前允许操作 |
| --- | --- |
| 空闲 | 开始 |
| 排队中 | 取消排队 |
| 运行中 | 暂停、终止 |
| 已暂停 | 继续、终止 |
| 失败、超时、中断 | retry、清理证据 |
| 已完成、已取消 | 清理证据 |

### 3.3 当前暂停与断点的边界

- 所有进入 `running` 的 V2 任务理论上都支持进程级暂停。
- 暂停按钮只在后端返回 `pause` 的运行窗口内出现。
- 短任务可能在页面刷新前已经完成，因此管理员看不到可操作的暂停按钮。
- 数据级 checkpoint 当前只存在于：
  - `buffs`
  - `bosses`
  - `town_npc_maintenance`
- 这三个域失败后 retry 使用 `auto`：断点有效则继续，无效则安全回到 fresh。
- 其余九个域失败后 retry 都是 fresh，但 fresh 不一定等于强制重抓。

## 4. 12 个注册域的当前真实行为

| 域 | 当前点击后的真实行为 | 可能很快完成的原因 | 当前数据影响 | 数据级断点 |
| --- | --- | --- | --- | --- |
| `items` | 检查物品 Wiki 模块 revision；变化或缺文件才抓取，并生成本地输出 | 无变化时计划为 `0/0` | 写任务证据；有变化时写来源和标准化文件；不写业务数据库 | 否 |
| `npcs` | 检查一个 NPC 信息模块，不是逐个 NPC 页面全量重爬 | 无变化时为 `0/0` | 写任务证据；有变化时写本地来源输出；不写业务数据库 | 否 |
| `projectiles` | 检查一个射弹信息模块，变化或缺文件才抓取 | 可能 `0/0`；即使抓取也只有一个模块 | 写任务证据；有变化时写本地来源输出；不写业务数据库 | 否 |
| `buffs` | 抓取 Buff 模板和免疫相关页面 | 多步骤长任务，通常不会秒完 | 写本地来源、解析结果、报告和断点文件；不写业务数据库 | 是 |
| `armor_sets` | 直接请求一次 Armor Set Bonuses 模块并更新本地输出 | 真实执行，但通常只有一次请求 | 写来源、标准化和报告文件；不写业务数据库 | 否 |
| `recipes` | 读取本地物品数据，生成关系包，执行数据库覆盖审计和 dry-run 导入 | 不是 Wiki 页面爬虫，主要是本地处理和数据库读取 | 写关系包和报告；连接数据库读取；当前不正式写数据库 | 否 |
| `biomes` | 抓取群系页面、转换并以 `apply=true` 导入数据库 | 属于完整流水线 | 写抓取和转换文件，并正式写数据库 | 否 |
| `bosses` | 逐页抓取 Boss 数据，历史任务约 33 页 | 长任务 | 写本地来源、报告和断点文件；不直接写业务数据库 | 是 |
| `town_npc_maintenance` | 逐页抓取 Town NPC maintenance 数据，历史任务约 39 页 | 长任务 | 写本地来源和断点文件；不直接写业务数据库 | 是 |
| `shimmer` | 直接抓取一个 Shimmer 页面及 revision | 单页面任务 | 写本地来源和报告；不写业务数据库 | 否 |
| `npc_loot` | 读取数据库和真实来源，计算普通 NPC 掉落差异并输出 dry-run 报告 | 不爬 Wiki 页面，也不正式写库 | 连接数据库读取并写报告；不写数据库 | 否 |
| `boss_loot` | 读取数据库和真实来源，计算 Boss 掉落差异并输出 dry-run 报告 | 不爬 Wiki 页面，也不正式写库 | 连接数据库读取并写报告；不写数据库 | 否 |

## 5. 已确认、不需要重复决定的要求

以下内容来自现有验收反馈，除非你在回填时明确推翻，否则作为固定约束：

1. 不要求把数据级断点续传覆盖到全部 12 个域。
2. 必须清楚区分同步、重新抓取、继续抓取、重新执行和重新排队。
3. 按钮不能隐藏真实行为；管理员点击前应知道任务实际做什么。
4. 暂停能力和适用范围必须可见，不能只能靠运行瞬间猜测。
5. 任务计划、进度、产物和结果必须来自真实数据，不允许用前端假数据补齐。
6. `0/0` 不能再无解释地等同于“重新爬取完成”。
7. 当前状态与最近一次任务结果必须能被管理员分别判断。
