# 文章合成树 PC 宽画布设计

## 目标

在 PC 文章详情中，让内嵌合成树使用文章主体面板的实际内容宽度，而不是受正文 `76ch` 阅读列限制。FW 等宽树必须保持全节点同屏，并把 `48px` 制作站源图在 1440px 桌面宽度下从约 `18.54px` 提升到约 `26px` 的可读尺寸。

## 已确认的根因

- `/articles/fw` 的合成图逻辑宽度为 `1706px`。
- 文章正文的 `76ch` 最大阅读列将嵌入树限制在约 `663px` 可用宽度，因此宽度适配比例为 `0.386`。
- 文章主体面板本身在 PC 网格中拥有更宽的实际内容区域；正文的行宽限制不应同时限制图形化的合成树。
- 恢复 `0.48` 最小缩放会重新裁掉外层节点，因此不能作为可读性方案。

## 方案

1. 新增一个纯计算 helper，输入当前嵌入树内容宽度、文章主体面板内容宽度和视口宽度。
2. 仅在 PC 断点（`960px` 及以上）取两者的较大值；移动端严格保留树自身内容宽度。
3. 在文章树创建前计算主体面板的可用内容宽度，将宽画布外部宽度写入嵌入树的 CSS 自定义属性，并以 `data-article-recipe-tree-wide="true"` 触发只针对合成树的 `max-width` 覆盖。
4. 合成图的初始缩放继续使用该宽画布的内侧可用宽度，保留已有四像素安全边距、完整节点边界、滚轮缩放与拖拽平移。

## 不做的内容

- 不改变制作页、富文本编辑器、配方 API、树形数据或右侧栏布局。
- 不扩大正文段落、标题、图片或其他文章引用的阅读行宽。
- 不为移动端增加横向宽画布；移动端保留现有可滚动、可缩放行为。
- 不再引入固定最小缩放比例。

## 验收

- 纯契约证明：1440px 的 PC 主体面板宽度会替代 `663px` 正文列宽；768px 视口不会替代它。
- `/articles/fw` 的图仍从宽度适配值开始，所有节点位于可见图框内，且没有文档级横向溢出。
- PC 实测站点图框大于原 `18.54px`，并完整使用 `contain`；侧栏矩形不与树矩形相交。
- `pnpm run check:article-content-references`、`pnpm exec vue-tsc --noEmit`、`git diff --check` 通过；可用本地后端时补充真实页面 Chromium 审核。

## 用户确认

用户于 2026-07-13 回复“继续”，确认采用 PC 宽画布、移动端保持现状的方案。
