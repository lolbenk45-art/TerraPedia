# 文章与编辑器合成树共享渲染器设计

## 目标

文章正式页与文章编辑器使用同一套合成树图形渲染管线，使节点尺寸、物品/制作站预览、名称/数量、归并、布局、缩放和拖拽行为一致。文章正式页继续保留其版本/配方选择与 PC 宽画布；编辑器继续保留富文本编辑职责。

## 根因

`pages/articles/[slug].vue` 和 `components/user/UserArticleRichEditor.vue` 各自复制了一套 `PublicItemRecipeTree` 处理代码：节点归并、坐标布局、DOM 图节点、popover、缩放和平移都分别实现。两套常量已分叉：编辑器使用 `102×54` 卡片、`18px` 制作站和 `0.48` 固定缩放下限；文章页使用完整图标与名称的 `132×100` 卡片、`48px` 制作站与宽度适配。

## 方案

1. 创建客户端通用模块 `front-nuxt/utils/recipeHierarchyGraphRenderer.ts`，拥有唯一的树归并、布局、节点 DOM、预览、popover、滚轮缩放和拖拽实现。
2. 模块接收根节点、最大层数、可用宽度、图片 URL 解析函数和 popover owner 标识，返回 graph DOM。宿主负责插入、销毁和各自的 shell/selectors。
3. 共享规格采用当前文章页的完整预览基线：`132×100` 常规卡片、`160px` 多配方卡片、`48px` 主物品及制作站预览、`32px` 替代材料、名称和数量直显、初始宽度适配且没有绝对 `0.48` 初始下限。
4. 文章页保留数据获取、版本/配方选择、正文宽画布计算和链接；编辑器保留 embed 识别、保存、contenteditable 禁用和编辑器容器尺寸读取。两端都把根节点和宿主宽度交给共享模块。
5. 合成树视觉规则移动到公共 crafting 样式域，并以一个共享 graph class 生效；移除 editor/article 侧各自的图形节点规格覆盖。

## 不做的内容

- 不改变 API、配方数据、文章 HTML 格式、编辑器保存协议或制作工作台 `RecipeHierarchyTree.vue`。
- 不改变文章版本/配方选择语义，也不让编辑器在此任务中增加新的选择器。
- 不修改移动端容器宽度策略；各宿主仍提供自己的可用宽度。

## 验收

- 源码契约证明文章页和编辑器都导入同一渲染器，且不再定义本地 graph card/scale 常量或本地 graph DOM 构建函数。
- 共享模块契约覆盖单根、替代材料、多配方来源、两制作站、缩放、平移与完整 `contain` 图片。
- 文章与编辑器使用同一 fixture 时，graph 的节点数、逻辑宽高、基准缩放、卡片规格和制作站规格一致；只有宿主可用宽度造成的比例差异允许存在。
- 文章 `/articles/fw` 保持全部节点可见、无图像裁切、无侧栏重叠；编辑器预览的树结构与节点样式一致。

## 用户确认

用户于 2026-07-13 在明确两套独立渲染器是视觉差距根因后回复“做吧”，确认采用共享图形树渲染器方案。
