# 文章合成树物品预览与制作页一致性设计

## 目标

使文章详情页内嵌合成树中的物品预览使用与制作页相同的可见像素居中逻辑，避免 PNG 透明留白或非中心内容导致物品看起来缩小、偏移或被裁切。

## 已确认的根因

- 制作页的 `CommonPreviewImage` 在图片加载后扫描 alpha 通道，计算实际可见像素的中心，并写入 `--tp-preview-visible-shift-x/y`。
- 文章页 `pages/articles/[slug].vue` 动态创建 `item-art tp-preview-image` 与原生 `img`，没有调用上述逻辑。
- 文章页图形节点的宽泛 `img { width: 38px; height: 38px; }` 规则还会覆盖各类预览的预期尺寸；特别是替代材料容器比该尺寸小，会产生裁切。

## 方案

1. 将 `CommonPreviewImage` 内的可见像素居中计算抽取到一个客户端可复用工具。
2. `CommonPreviewImage` 调用该工具，保持制作页现有行为不变。
3. 文章动态树创建图片时，在图片 `load` 后调用同一工具；图片节点补齐通用组件输出的 `data-source-image` 标记和失败回退语义。
4. 文章树只保留与实际容器一致的预览尺寸约束，不再以通用的 `38px` 覆盖所有图像。

## 范围

- 修改：公共预览居中工具、`components/common/PreviewImage.vue`、`pages/articles/[slug].vue`、文章树契约检查。
- 不修改：接口、配方数据、`RecipeHierarchyTree.vue` 的结构与视觉规格、富文本编辑器、其他视觉审查项。

## 错误与兼容

- 图像未加载、跨域画布读取失败、尺寸无效或像素超出安全扫描阈值时，重置偏移为 `0px`，按既有图片自然居中显示。
- 图片容器尺寸变化时，制作页仍会重新计算；文章动态树在加载时计算即可，因为其图形布局不支持单独调整图标尺寸。

## 验证

1. 先扩展文章树契约，使其在现状下因缺少共享居中调用及 38px 冲突规则而失败。
2. 完成最小实现后运行该契约、`pnpm run check`、浅色主题运行态检查与 `git diff --check`。
3. 在运行中的 `/articles/article` 和 `/crafting?itemId=4731` 对比同类预览：文章预览必须拥有来源标记与非零或正确的可见区域偏移，且无裁切或容器溢出。
